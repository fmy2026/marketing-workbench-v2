## AC-02：四种场景适用性

| 静态场景 | 对应起点与必要补充 | 边界核对 |
|---|---|---|
| 研究报告 | 路径开放、产物可审阅；单 Agent 配工具、来源证据、预算与停止条件 | 文件可存来源和产物；未要求数据库、长期记忆或多 Agent；缺证据不能宣称成功 |
| 编程修改 | 实现路径可探索；复用编程 Agent，借助代码、测试与差异验证 | 代码草稿可审阅；合并、发布等动作另按授权和后果加执行控制；不要求自建运行底座 |
| 固定周报 | 固定取数、计算和校验工作流，必要处调用模型生成说明 | 报表与粒度按真实需要设计；不要求自主 Agent；对外发布需落实相应授权和防重复 |
| 业务写入 | 固定流程、权限与结果核验；局部开放判断受边界控制 | 外部结果不明先查实际状态；长期等待、多人身份等条件叠加；开发 Task 不代替产品运行记录 |

四行选型是默认起点，可叠加长任务、多 Agent、多用户、实时交互条件；未将研究/编程/业务名称与固定架构绑定，也未将生产成熟度写成 Agent 数量升级路线。全文明确数据库、业务报表及跨任务记忆按需建设，架构复用和自建边界需选择。

新增/变更区域的 17 个链接（含目录及引用重复项）与锚点已核验有效。原知识库文件仅作方法参考；本次未复核其中近期产品公告或引入供应商版本断言。AGENTS、package、开发 Task/Manifest 与产品运行机制的职责区分明确，原权威文件未改写。
