# JSZC Attempt 1 `40000` 创建字段差异排查

## 1. 需求、范围与结论边界

### 需求

排查目标账户 `1871922346964041` 的 JSZC 标准项目 Attempt 1 为什么未获平台确认，并将其与历史成功账户 `1871922175825993` 的项目 `7675218401040220179` 做字段级差异比对；同时复核创建字段收口 Task 是否存在错改。

### 范围

- 官方合同：本机 3.0 `std_project/create` 与 `std_project/list` 资料。
- 不在范围：第二次创建、任何资源写入、预算/出价调整、token 刷新、完整请求或响应的恢复。

### 安全记录边界

本报告依用户授权保留账户、项目、Job/Draft/Plan 和 hash 标识，并记录非敏感字段的枚举、数量、长度及数值。仍不记录 token、Cookie、完整 URL、原始请求/响应、完整当前 payload，或当前账户的可直接复用资源 ID。当前素材、抖音号、小游戏实例、事件资产、品牌和 DMP 均以“目标账户已只读核验 + hash/数量/长度”表达。

### 结论先行

1. Attempt 1 未被平台确认创建，但 `40000 + resource_not_eligible` 没有安全可记录的字段路径；它**不能**证明某一字段、素材或收口改动错误。
2. 当前草稿在本地合同层通过：82 条创建字段账本路径、21 条嵌套路径、payload contract、create preflight 与查重均通过。Node 5 的 `needs_confirmation` 是真实写入前的人工闸门，不是字段 blocker。
3. 与历史成功项目相比，当前存在若干“官方允许但尚无目标账户真实创建证明”的差异。优先级最高的是：默认视频封面、`external_url_material_list` 省略、`image_material_list=[]`；其次是 URL-only 小游戏链路、无 `schedule_time`、CTA 数量和定向策略差异。
4. `TASK-MWBV2-OE3-JSZC-CREATE-FIELD-CLOSURE-20260829` 的技术改动没有已证实的错改；其中外链省略、空图片数组和静态开关组合仍属高优先级“未经过真实创建验证”，不能再表述为平台已验证的安全默认。
5. 当前最小动作是先做目标账户的只读复核与合同证据补强；不应把多个候选字段一起回填后直接进入 Attempt 2。

## 8. 失败归因边界与候选排序

### 已证实

- 平台收到了一次 create 请求并给出业务失败码 `40000`。
- 未返回项目 ID；三次 list 均未发现同名对象；本次创建未确认成功。
- 安全分类为 `resource_not_eligible`，具体字段路径为空。
- 执行器关闭了写入 scope，未自动进入 Attempt 2。

### 未证实、不得宣称

- 不能说抖音号、小游戏实例、事件资产、品牌、DMP、视频、产品图中的任一项不合格。
- 不能说外链省略、空图片数组、URL-only、默认封面、无 `schedule_time` 中任一项导致 `40000`。
- 不能因为历史项目发送了 `micro_promotion_type` 或 `app_id`，就把它们自动补回当前 payload。

### P1 已完成：视频默认封面目标账户只读验证

P1 只读 Job `JOB-MWBV2-20260829163317-C97C14` 已在不打开平台写入 scope 的条件下完成。只调用目标账户 2 次 `file/video/get` 与 2 次 `file/image/get`：两条必选视频均可见，但两张对应封面均未命中目标账户。
