# V2 项目创建失败原因排查（2026-08-28）

## 结论摘要

本次 V2 标准项目创建请求的 HTTP 状态为成功返回，但平台业务码为通用 `40000`，且已按安全规则只保留脱敏错误摘要与 hash，未保留 raw request / raw response。因此，不能仅凭平台响应断言某一个字段是唯一直接原因。

不过，现有 V2 payload 与成功项目、官方 3.0 创建合同及当前代码链路对照后，已发现多项可独立导致创建失败或造成平台拒绝风险的字段问题。应先在草稿阶段阻断这些问题，再以 fresh job 从零生成一套新 payload；不得复用失败 draft，也不得直接重试当前失败创建。

## 失败原因分级

### P0：`aweme_id` 语义错误

- **现状**：V2 将头像资源的 `platform_resource_id` 回退写入 `aweme_id`；实际值形态为 `web.business.image/...`。
- **为什么是高风险**：官方合同中的 `aweme_id` 是已授权抖音号 ID，来源应为“获取抖音号授权关系”。头像图片资源 ID 只能证明头像素材已准备，不能证明存在、也不能替代已授权的抖音号。
- **代码根因**：payload builder 在缺少 `metadata.default_aweme_id` / `metadata.aweme_id` 时，回退到 avatar 的 `platform_resource_id`；现有 preflight 仅验证字段是否存在，未验证来源、资源类型或 ID 语义。
- **修正原则**：只允许从经只读授权关系查询并持久化为“已验证身份”的记录生成 `aweme_id`；任何 `web.business.image/`、URL、图片 ID 或无法追溯授权关系的值必须在草稿阶段阻断。

### P1：商品卖点不满足官方长度限制

- **现状**：当前默认卖点为“策略开荒”“巨兽养成”“联盟对战”，均为 4 个汉字。
- **官方合同**：`product_info.selling_points` 的每一项长度必须在 `[6, 9]`。
- **风险**：即使其他字段正确，该嵌套字段也可能造成平台校验拒绝；当前 preflight 未检查卖点长度。
- **修正原则**：仅保存、选择和发送 6–9 字的卖点；生成后按 Unicode 字符数逐项校验，例如以成功项目中已验证的同类文案结构作为质量基准，但不复制任何平台资源 ID、链接或敏感请求内容。

### P1：标题候选会回退为内部素材文件名

- **现状**：当缺少足够的业务标题时，构建器会使用素材资产名作为 `title_material_list[].title` 候选。
- **风险**：内部文件名不是广告文案，可能包含无业务含义的命名、扩展名或不符合官方长度/质量要求的文本；当前仅聚合展示数组，未逐条按嵌套路径校验。
- **修正原则**：标题必须来自人工确认或受控生成的广告文案库；禁止以 asset name / 文件名 / 内部标识符回退。逐条校验标题非空、长度范围、无文件扩展名与无内部路径特征。

### P2：官方创建字段被字段合同错误省略

- **现状**：`delivery_type` 与 `layer_roi_switch` 已在官方创建接口合同中定义，成功项目也带有对应的稳定配置；但当前字段合同将前者标为“相关接口证据”、后者标为“未验证”，并以 `omit` 策略从最终 payload 删除。
- **风险**：这不是已被平台响应单独证实的直接报错字段，但会使 V2 发送形态偏离成功项目和官方 create 合同，削弱“高仿成功项目”的可复现性。
- **修正原则**：更新字段合同：`delivery_type` 发送 `NORMAL`，`layer_roi_switch` 发送 `OFF`；`micro_promotion_type` 继续按其独立合同决定是否省略，不能借此推断其他字段也应省略。

### P2：校验只验证顶层存在性，未验证嵌套字段语义

- **现状**：现有 create preflight 能发现部分顶层字段缺失和若干格式问题，但 `aweme_id` 只检查存在性；对卖点、标题和其他嵌套字段缺少逐路径的合同与语义校验。
- **影响**：错误草稿被标记为 preflight passed，直到真实创建时才得到无法定位到字段的通用失败。
- **修正原则**：将字段合同校验扩展为路径级校验；失败时在 draft / skill 结果中记录字段路径、规则标识和脱敏修正建议，不记录 raw payload。

## Task 记录字段

运行事实必须继续以 Postgres 为准；本文件只定义应记录的安全字段，不复制动态运行状态、完整请求、完整响应或完整监测链接。

| 记录类别 | 必须字段 | 用途与约束 |
| --- | --- | --- |
| 闭环归属 | `case_id`、`job_id`、`draft_id`、`attempt_no`、`plan_id` | 一个 case 可有多个 fresh job；失败 draft 只读保留，不作为新创建输入。 |
| 草稿版本 | `payload_hash`、字段 manifest hash、合同版本、构建时间、阻断码 | 只存 hash 和脱敏 manifest，不存 raw payload。 |
| 平台动作 | `request_hash`、`response_hash`、HTTP 状态、API 码、安全错误类别、脱敏错误摘要、动作状态 | 不将请求 ID、raw response、token 或完整 URL 写入 Markdown、普通日志或前端。 |
| 资源证据 | 资源类型、资源状态、readback 状态、证据 hash、授权身份来源标识 | avatar 与抖音号身份必须为不同资源类型。 |
| 字段快照 | 发送字段路径、是否发送、来源类别、合同规则、校验结果、值 hash / 安全形态摘要 | 真实 `platform_actions` 创建记录当前缺少可审计的 request field manifest；后续需补齐。 |
| 工作流执行 | Node 状态、Skill 状态、blocker codes、建议下一 gate | Node / Skill 结果分别写入既有运行表，不在 Markdown 手写 current gate。 |

## 数据库存储逻辑

```text
workflow_cases
  └─ launch_jobs（同一 case 可创建多个 fresh job）
       ├─ project drafts / execution plans / payload hash
       ├─ launch_node_runs + launch_skill_runs
       ├─ resources + resource readback / evidence
       ├─ platform_actions（安全摘要、hash、字段 manifest）
       └─ readback 结果

workflow_case_summary
  └─ 由以上最新运行事实投影当前 gate、blocker 与建议下一动作
```

- `workflow_cases` 是业务闭环总控；新 runtime job 必须显式继承指定 `case_id`，不得因广告账户相同而自动合并。
- `launch_jobs`、draft、execution plan 与 attempt 共同表达一次可审计的创建尝试；重走时创建新的 job、draft 与 plan 版本。
- 资源、节点/skill、平台动作和回查均只保存必要 ID、状态、证据摘要和 hash；平台长数字 ID 按字符串处理。
- 当前数据库具备头像、DMP、事件、视频、商品图、品牌、小游戏实例等资源记录，但缺少“账户—已授权抖音号身份”的独立实体或等价的经验证字段。因此不能从 avatar 资源表推导 `aweme_id`。
- 建议新增独立的授权抖音号身份存储：至少包含广告账户归属、`aweme_id`、授权关系查询时间、验证状态、来源证据 hash、是否默认身份与失效状态；不保存 token、Cookie、raw response 或完整回调 URL。
- `platform_actions` 在真实创建时应写入脱敏 request field manifest，至少能回答“某字段是否发送、来自哪个已验证来源、通过了哪条合同规则”；不可存储完整字段值或 raw payload。

## 子节点与工作流调整

现有流程维持“三阶段、七节点”的唯一注册表，不复制第二套节点定义。调整仅落在既有 Node 4 与 Node 5 的子能力上。

| 节点 | 调整 | 输出 / 阻断条件 |
| --- | --- | --- |
| Node 4：账户资源准备 | 新增只读“抖音号授权身份”准备子能力；调用授权关系查询或读取其受控结果，要求用户在多身份时明确选择默认身份。 | 仅在身份与广告账户匹配、授权有效、来源可追溯时标记 ready；否则写 `aweme_identity_not_verified` blocker。 |
| Node 5：标准项目草稿构建 | `aweme_id` 仅取 Node 4 的 verified identity；增加路径级嵌套合同校验；采用成功项目同构的字段策略。 | 阻断图片 URI / 素材 ID `aweme_id`、非法卖点、内部文件名标题、未验证身份和不符合发送策略的字段。 |
| Node 6：创建执行 | 保持显式确认、执行计划授权和“一次创建”约束；只接受 Node 5 无 blocker 的新 draft。 | 无独立授权不得执行；不得复用失败动作的 request。 |
| Node 7：回查闭环 | 保持创建后读取项目对象与回查记录；即使创建响应缺少对象 ID，也执行安全回查。 | 只有读到目标项目对象后才标记创建闭环成功。 |

## 从零重走方案

1. 在原 case 下创建一个 **fresh job**，并生成新的 draft、execution plan 与 payload hash；当前失败 draft、失败 action 和历史 attempt 仅作为只读对照证据。
2. 在 Node 4 完成账号授权抖音号身份的只读验证与选择；没有有效身份时停止，不进入草稿构建。
3. 在 Node 5 以已验证身份生成 `aweme_id`，将商品卖点改为每项 6–9 字的受控文案，替换任何文件名标题，并发送 `delivery_type=NORMAL`、`layer_roi_switch=OFF`。
4. 运行路径级 preflight：逐项输出阻断字段路径与规则；通过后固化脱敏字段 manifest、payload hash 和合同版本。
5. 人工确认新 job / draft / plan 与创建范围；获得独立的真实平台创建授权后，Node 6 仅执行一次创建。
6. Node 7 读取目标项目对象并写入安全回查结果；仅当回查成功时将该 fresh job 标记为闭环成功。

## 验收条件

- 草稿阶段必定阻断：图片 URI / `web.business.image/...` 形式的 `aweme_id`、未验证授权身份、6 字以下或 9 字以上的卖点、内部文件名标题。
- 最终 payload 的发送策略与官方 create 合同一致，且对照成功项目保留同构的必要字段；不复制成功项目的资源 ID、账户 ID、完整 URL 或 raw 请求内容。
- 每个新草稿有 payload hash、合同版本和脱敏字段 manifest；每个真实平台 action 有 request / response hash、API 码、安全错误摘要及对应字段 manifest。
- 未获得新的显式平台写入授权前，系统只能完成准备、草稿、校验和只读回查，不能发起第三次创建。
- 真实创建后必须读取到目标项目对象并完成回查，才可认定为创建成功。
