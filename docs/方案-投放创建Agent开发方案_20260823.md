## Summary

## 工作台模块维度

| 模块 | 定位 | 第一版范围 |
| --- | --- | --- |
| 对话入口模块 | 用户用自然语言输入需求，Agent 追问缺参 | 识别 `route_id`、`game_slug`、`advertiser_id` |
| LLM 配置模块 | 配置需求理解模型 | 模型、API Key、连接状态，先只服务 Intake |
| 投放创建 Agent | 工作台主控 Agent | 统一调度 Intake、诊断、补齐、草稿、执行、回查 |
| Workflow 看板模块 | 展示 3 阶段 7 节点状态 | 右侧节点、子流程标签、进度、卡点、按钮状态 |
| 诊断报告模块 | 汇总每个节点的通过、卡点、需确认状态 | 弹窗表格展示阶段、节点、状态、问题、动作 |
| 游戏保底包模块 | 按 `game_slug + route_id` 装配投放所需默认配置 | 游戏产品、品牌类目、投放目标、预算出价、素材包、DMP |
| 账户上下文模块 | 装配目标账户的投放上下文 | 账户授权、监测序号、触点 ref、平台版本 |
| 账户资源模块 | 检查和补齐创建前账户资源 | 头像、DMP、事件链、视频可见性、产品图、品牌回查 |
| 创建草稿模块 | 生成最终创建 payload | 项目名、payload、hash、查重、写入策略 |
| 确认执行模块 | 管控平台写入 | 一键确认、单次写入、写入边界、结果记录 |
| 回查收口模块 | 创建后验证结果 | 对象 ID、状态、字段一致性、证据归档、下一步 |
| 经验知识模块 | 保存成功路径和可复用判断 | 第一版只记录证据和候选经验，不做复杂推荐 |
| 素材策略模块 | 后续独立 Agent | 第一版只作为投放创建里的素材包解析能力 |
| 归因分析模块 | 后续独立 Agent | 第一版不做投后归因，只预留证据结构 |

## 3 阶段 7 节点

| 阶段 | 节点 | 子流程 | 输出 |
| --- | --- | --- | --- |
| 准备阶段 | 1. Intake 规范 | 路线、游戏、账户 | `launch_intake` |
| 准备阶段 | 2. 创建上下文装配 | 监测序号、触点 ref、账户授权、平台版本 | `creation_context` |
| 准备阶段 | 3. 游戏保底包解析 | 游戏产品、品牌类目、投放目标、预算出价、素材包 | `game_launch_pack` |
| 就绪阶段 | 4. 账户资源诊断与补齐 | 头像、DMP、事件链、视频可见、产品图、品牌回查 | `account_ready_report` |
| 就绪阶段 | 5. 创建草稿生成 | 项目名、Payload、查重、Hash、写入策略 | `creation_draft` |
| 创建执行 | 6. 创建执行 | 一键确认、单次写入、边界锁定 | `created_object` |
| 创建执行 | 7. 回查收口 | 对象 ID、状态、字段一致、证据归档、下一步 | `readback_verified` |

## Skill 与自动化脚本规划

| 节点 | 新项目 Skill | 自动化能力 |
| --- | --- | --- |
| Intake 规范 | `launch_intake` | 自然语言解析、缺参追问、路线归一 |
| 创建上下文装配 | `creation_context_resolver` | 账户查询、监测序号创建/查询、触点 ref 解析 |
| 游戏保底包解析 | `game_launch_pack_resolver` | 从 Postgres 读取游戏、路线、素材、预算、DMP 默认包 |
| 账户资源诊断与补齐 | `account_resource_prepare` | 头像、DMP、事件链、视频/产品图可见性、品牌回查 |
| 创建草稿生成 | `std_project_draft_builder` | 命名、payload 编译、查重、hash、写入策略 |
| 创建执行 | `std_project_create_executor` | 确认校验、单次 `std_project/create`、结果记录 |
| 回查收口 | `readback_closer` | `std_project` 回查、字段 diff、证据归档 |

## Workflow 节点细化

| 节点 | 输入 | 关键动作 | 成功条件 | 常见卡点 |
| --- | --- | --- | --- | --- |
| 1. Intake 规范 | 用户自然语言 | 抽取并归一 `route_id`、`game_slug`、`advertiser_id` | 三核心字段齐全 | 用户只说渠道/游戏，未给账户 |
| 2. 创建上下文装配 | Intake 输出 | 查询账户、创建/查询监测序号、解析触点 ref | `creation_context` 可用 | 监测序号 API 不返回 `monitor_id/touchpoint_url` |
| 3. 游戏保底包解析 | `route_id + game_slug` | 读取游戏产品、品牌类目、目标、预算、素材、DMP | `game_launch_pack` 齐全 | 素材包、预算出价、DMP 默认值缺失 |
| 4. 账户资源诊断与补齐 | 上下文 + 保底包 | 检查/补齐头像、DMP、事件链、视频、产品图、品牌回查 | `account_ready_report` 通过 | 事件配置缺失、DMP 目标账户不可见、品牌回查不匹配 |
| 5. 创建草稿生成 | ready 报告 | 生成项目名、payload、payload hash、查重结果 | `creation_draft` 可确认 | 同名项目已存在、payload 缺字段 |
| 6. 创建执行 | 草稿 + 确认 | 单次执行 `std_project/create`，记录动作 | 返回 `std_project_id` | API 失败、权限失效、限频 |
| 7. 回查收口 | 创建对象 ID | 回查对象状态和关键字段，归档证据 | `readback_verified` | 创建返回成功但回查延迟或字段不一致 |

## API 接口

| 接口 | 用途 |
| --- | --- |
| `POST /api/launch/intake` | 解析自然语言，返回三核心字段和缺参 |
| `POST /api/launch/jobs` | 创建投放创建任务，初始化 7 节点 |
| `GET /api/launch/jobs/:job_id` | 返回对话摘要、Workflow 状态、诊断报告、草稿 |
| `POST /api/launch/jobs/:job_id/diagnose` | 运行诊断，更新节点状态 |

| `POST /api/launch/jobs/:job_id/confirm` | 确认创建草稿 |
| `POST /api/launch/jobs/:job_id/readback` | 触发或刷新创建后回查 |

## Test Plan

- Intake 缺参时只追问，不创建任务。
- 监测序号 API 未返回 `monitor_id/touchpoint_url` 时停在“创建上下文装配”。
- 游戏保底包缺关键字段时诊断报告明确缺口。
- 账户资源缺头像、DMP、事件链、视频或产品图时进入“可修复/需确认/阻断”状态。
- 创建草稿必须生成稳定 payload hash，并完成同名查重。
- 创建执行最多一次 `std_project/create`。
- 回查必须验证对象 ID、对象状态、关键字段一致性。
- 安全测试必须阻断 token、Cookie、完整触点 URL、raw payload、raw response 泄漏。

## Assumptions

- 第一版只支持 `oceanengine_3_byte_mini_game`。
- 第一版最终创建对象只支持 `std_project`。
- 参考文件用于开发设计和字段经验，不作为新项目运行依赖。
- 新项目应把脚本能力重新封装到自己的目录，不能直接依赖旧项目路径。
- 完整触点 URL 只允许进入受控敏感存储，普通表、日志、API 和文档只展示 ref/hash/status。
