# TASK-MWBV2-INTAKE-START-CONSISTENCY-20260921

任务状态、读取清单与验证结果：[Context Manifest](../tasks-context-manifests/TASK-MWBV2-INTAKE-START-CONSISTENCY-20260921.json)。

## 目标

修复新建项目多轮 Intake 在服务端已校验完整后仍无法显示启动按钮的问题，同时保持受控启动、账户预检、Plan 确认与平台写入边界。

## 批准方案

采用已批准的最小闭环修复：服务端合并草稿后再决定是否调用模型；前端以服务端 `can_start` 与已校验请求快照作为唯一启动依据；模型回退仅作诊断。同步帮助示例与当前机制文档。

## 范围

修改 Intake 解析、投放执行工作台启动卡和相关隔离测试；更新方案、流程与部署文档；建立本次验收证据并按 main 交付、发布和重载当前公司模式。

## 非目标

不修改 LaunchRequest 版本、数据库、Node、Gate、Plan、账户归属或平台执行器；不创建、确认、重试或写入任何真实平台对象。

## 验收

- AC-01: 多轮新建项目输入在合并后形成完整规则请求时，不调用模型，页面显示唯一可点击启动卡且顶部状态一致。
- AC-02: 模型成功、超时、低置信、非 JSON 和证据拒绝均保持安全分类；完整规则请求不被模型回退额外阻断。
- AC-03: 缺项、冲突、无效游戏、事项切换、输入编辑和非法 JSON 仍不能启动，未经验证模型值不进入请求。
- AC-04: 浏览器隔离验证启动只提交一次，Case／Job 使用同一冻结请求，未确认时平台写入为零。
- AC-05: 追加视频、JSON、账户隔离、确认边界与项目合同检查通过；发布后工作台使用该修复版本。

## 停止条件

发现修复需要扩大到数据库、Gate、平台执行器或真实平台写入时停止；任何验收未通过不得关闭或发布。
