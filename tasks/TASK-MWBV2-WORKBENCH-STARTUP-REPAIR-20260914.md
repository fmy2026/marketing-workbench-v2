# TASK-MWBV2-WORKBENCH-STARTUP-REPAIR-20260914

任务状态、读取清单与验证结果：[Context Manifest](../tasks-context-manifests/TASK-MWBV2-WORKBENCH-STARTUP-REPAIR-20260914.json)。

## 目标

修复固定 release 无法读取共享乾坤凭据的问题，并让投放创建页以单一、与当前 Gate 一致的只读核验入口和即时侧栏呈现真实状态；追加视频的只读检查须使用正确的项目素材过滤参数、大小写敏感的素材标识码匹配和保留原始字符串视频 ID 的素材推送 Plan，并把真实阻断同步到 Case 投影。已确认追加后必须通过独立只读回查收口；明确平台拒绝且仍未可见时才可建立同一 Case 的 fresh 追加恢复 Job。

## 批准方案

用户批准“恢复凭据读取，收拢启动入口”：发布运行时显式使用共享凭据文件；完整 Intake 仅在最新对话下显示一个启动卡片；启动后立即展示真实请求阶段，只有取得 Job 才显示服务端七节点进度。

## 范围

允许修改工作台发布环境、乾坤凭据路径解析、追加视频只读查询与状态投影、Plan 执行后的权威回查收口、`workflow_case_summary` 投影、投放创建前端及相应回归测试和当前文档。工作台对话仅在当前页面内保留用户决策与解析回复，轮询不得覆盖既有轮次。所有平台请求保持既有 readonly/Plan 确认链。

## 非目标

不修改数据库结构、公开 API、Node/Gate、账户预检规则或任何平台写入；不复制、记录或输出凭据内容。

## 验收

- AC-01: 固定 release 与开发目录均解析到同一共享乾坤凭据文件，发布检查在文件缺失时失败。
- AC-02: 完整自然语言或 JSON Intake 只显示一个有效启动卡片；输入变化立即失效，点击期间按钮显示“启动中…”。
- AC-03: 启动即时显示侧栏；`run_fresh_readiness` 只显示“开始只读核验”且兼容“重新只读准备”，`resolve_case_blocker` 才显示“重新只读准备”；预检、建 Job、运行及失败只展示真实阶段，Job 存在时显示服务端节点进度。
- AC-04: 浏览器回归覆盖启动点击、重复点击、输入失效、失败反馈和窄屏；现有工作台与项目检查通过。
- AC-05: 新 release 在公司模式启动，静态页面和共享凭据路径均由实际运行版本核验。
- AC-06: 追加视频的项目素材只读查询使用官方 `filtering.material_type`；素材标识码在输入、查询、库存匹配、Plan 和阻塞提示中保持原始大小写，歧义来源和查询失败形成唯一真实 blocker，页面不展示新建项目的无关检查项。
- AC-07: 目标账户缺少、物料户唯一命中的视频生成独立 `project_video_material_push` Plan；`video_ids` 保持原始非空字符串及大小写，Plan 构建失败保留真实原因，推送 Plan 的本人确认资格与服务端一致，右侧标题固定显示事项、3 阶段和 7 节点。
- AC-08: 素材推送的成功动作与权威库存回查分别落库；回查通过后自动重跑同一 Job 的只读准备，过滤项目已有视频并仅生成待追加视频的独立确认 Plan。回查未确认时保留真实 blocker，禁止重发已消费的推送 Plan。
- AC-09: 追加请求以无损 JSON 整数发送账户和项目 ID、以原始字符串发送视频 ID；已确认追加的 Gate 只提供结果回查。平台明确拒绝且回查仍缺失时，用户可建立唯一 fresh 追加恢复 Job。输入、快捷入口和确认卡均追加用户决策及原位解析回复，轮询不覆盖历史轮次。
