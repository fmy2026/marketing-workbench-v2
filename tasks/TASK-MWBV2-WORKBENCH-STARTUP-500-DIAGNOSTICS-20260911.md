## 目标

为工作台“启动流程”的未分类 5xx 提供受控阶段与诊断码，并记录安全的本地诊断信息，以定位新账户启动失败原因。

## 批准方案

用户批准：前端在创建 Case、创建 fresh Job 与启动 readonly 三阶段标记请求；5xx 仅显示阶段与脱敏诊断码。服务端只为 5xx 写入方法、路径、阶段、指纹、受控错误码和不含错误消息的栈帧。保持 API 的 `internal_error` 脱敏边界、既有 Gate 与权限不变；完成后仅对截图账户启动一次以读取诊断，不确认或执行平台写入。

## 范围

- 更新工作台前端、服务端 5xx 诊断、两份相关 smoke 与当前逻辑图。
- 通过既有本机工作台对截图账户发起一次启动流程，读取本地脱敏诊断日志。
- 允许写入不含账户标识或原始异常的本地验证证据。
- 允许更新本 Task、Context Manifest 与项目当前任务指针。

## 非目标

- 不改变账户归属、Case/Job、Node、Gate、Plan、确认或平台写入机制。
- 不暴露错误消息、请求体、Cookie、凭据、完整 URL、原始平台请求或响应。
- 不自动重试、不确认、不创建平台对象或刷新 OAuth。

## 验收

- AC-01: 启动流程的 5xx 显示受控阶段和脱敏诊断码，不显示原始异常；既有 4xx blocker 显示不变。
- AC-02: 服务端 5xx 本地诊断仅含安全字段，响应仍为脱敏 `internal_error`；相关 smoke 通过。
- AC-03: 对截图账户仅发起一次启动流程，记录诊断结果并确认未执行 confirmation 或平台写入。

## 停止条件

如实现需要扩大业务行为、泄露敏感信息、自动重试、确认或平台写入，或截图账户启动将执行此范围外操作，停止并保持现有行为。

完成后，新账户启动失败可由用户可见诊断码与本地安全日志定位；发现的具体业务/数据问题不在本 Task 直接修复。
